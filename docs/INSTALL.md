# Установка и подключение

## 1. Требования

- Joomla 6.x, PHP 8.3 или новее, MySQL 5.7+/MariaDB 10.4+.
- **HTTPS** на сайте. По HTTP сервер откажет (токены нельзя передавать открыто). Для локальной проверки это можно отключить в настройках.
- Права на запись в `tmp/` (там хранятся резервные копии файлов, если включены наборы «Шаблон» и «Система»).
- Для набора «Магазин» — установленный Dharma Shop.

## 2. Получение пакета

**Готовый:** на странице [релизов](https://github.com/shivayanamahom/dharma-mcp/releases) скопируйте ссылку на файл `pkg_dharma_mcp-<версия>.zip` и вставьте её в Joomla (раздел 3).

**Сборка из исходников.** Из корня репозитория:

```bash
./build.sh
```

Скрипт проверит синтаксис всех PHP-файлов и соберёт `dist/pkg_dharma_mcp-<версия>.zip`. Внутри пакета — вложенные архивы: компонент `com_dharma_mcp`, системный плагин адресов и четыре плагина-набора.

## 3. Установка на сайт

1. Joomla → **Система → Установка → Расширения → Установка из URL** → вставьте ссылку на пакет (или вкладка «Загрузить файл пакета», если файл уже скачан).
2. При первой установке автоматически включаются: системный плагин «Dharma MCP (адреса)», наборы **Магазин** (если установлен Dharma Shop) и **Материалы и меню**.
3. Наборы **Шаблон** и **Система** остаются выключенными. Включайте их осознанно: **Система → Плагины**, группа `dharmamcp`. Пока набор выключен, его инструментов нет вообще.

## 4. Настройки

**Компоненты → Dharma MCP → Настройки.**

| Настройка | Что делает |
|---|---|
| Включить MCP-сервер | выключатель: при «Нет» все запросы получают 503 |
| Требовать HTTPS | по умолчанию да |
| Режим работы | *Только чтение* / *Чтение и черновики* (по умолчанию) / *Полный доступ* |
| Разрешить вход через OAuth | нужен для Claude Desktop, claude.ai и ChatGPT |
| Разрешить регистрацию клиентов | клиенты MCP регистрируются сами (RFC 7591) |
| Разрешить выдачу персональных данных | по умолчанию нет: имена, телефоны, адреса покупателей скрыты |
| Маскировать персональные данные | если разрешены: показывать частично |
| Срок хранения журнала | по умолчанию 90 дней |
| Лимит запросов в минуту | на один токен, по умолчанию 60 |

Режимы:

- **Только чтение** — ничего нельзя изменить.
- **Чтение и черновики** — можно создавать неопубликованное; любое изменение «живых» данных (опубликованная статья, цена, статус заказа) требует подтверждения; опасное — всегда с подтверждением.
- **Полный доступ** — «живые» изменения без подтверждения; опасное (файлы, настройки, плагины) — по-прежнему всегда с подтверждением.

## 5. Токен доступа

**Компоненты → Dharma MCP → Токены доступа → Создать.**

- **Пользователь Joomla** — от его имени выполняются действия. Токен не может больше, чем сам пользователь. Для набора «Система» и записи файлов нужен Суперпользователь.
- **Области** — отметьте минимум необходимого: `shop:read`, `shop:write`, `content:read`, `content:write`, `template:read/write`, `system:read/write`, `customers:pii`.
- **Срок действия** — для опасных областей ставьте короткий.
- **Разрешённые IP** — необязательно (адреса и сети вида `10.0.0.0/8`).

После сохранения Joomla **один раз** покажет токен вида `dhmcp_…`. Сохраните его в менеджере паролей: в базе хранится только хэш.

## 6. Подключение клиентов

Адрес сервера: `https://ваш-сайт/mcp`. Если на сайте не включены ЧПУ с перезаписью адресов, используйте `https://ваш-сайт/index.php?option=com_dharma_mcp&format=json`.

> Порядок действий в интерфейсах Claude и ChatGPT меняется. Перед работой сверяйтесь с текущей справкой производителей.

**Claude Code** (по токену):

```bash
claude mcp add --transport http dharma https://ваш-сайт/mcp --header "Authorization: Bearer dhmcp_ВАШ_ТОКЕН"
```

**Claude Desktop / claude.ai:** Настройки → Коннекторы → добавить свой коннектор → адрес `https://ваш-сайт/mcp`. Откроется страница входа Joomla и экран согласия, где вы выбираете, что разрешить. Токен вводить не нужно.

**ChatGPT:** Настройки → Коннекторы → режим разработчика → добавить свой MCP-сервер → тот же адрес, тип авторизации OAuth.

**Cursor и свои скрипты:** адрес и заголовок `Authorization: Bearer …` в настройках клиента.

Подключения OAuth можно отозвать в **Токены доступа** (они помечены «OAuth: имя клиента»).

## 7. Особенности хостинга

**Заголовок Authorization.** На части хостингов (PHP как CGI/FastCGI) Apache не передаёт PHP заголовок `Authorization`, и сервер отвечает «Missing or malformed Authorization header», хотя токен указан верно. Добавьте в `.htaccess` сайта, до правил Joomla:

```apache
RewriteEngine On
RewriteCond %{HTTP:Authorization} .
RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
```

Сервер читает `HTTP_AUTHORIZATION`, `REDIRECT_HTTP_AUTHORIZATION` и `apache_request_headers()`.

**Адреса `/mcp` и OAuth на nginx (и вообще без перезаписи адресов).** Короткие адреса `/mcp`, `/oauth/*` и `/.well-known/*` обслуживает системный плагин «Dharma MCP (адреса)», но запрос должен дойти до Joomla. Это зависит от сервера:

- **Apache:** достаточно штатного `.htaccess` Joomla (файл `htaccess.txt` нужно переименовать в `.htaccess`) и включённой перезаписи адресов.
- **nginx без перезаписи** (признак: страницы вашего сайта выглядят как `/index.php/...`, а `/mcp` отвечает 404 от nginx): адрес `https://ваш-сайт/index.php/mcp` работает сразу, для токенов этого достаточно. Для **OAuth (Claude, ChatGPT)** клиенты ищут настройки по адресам в корне сайта, поэтому добавьте в блок `server {}` конфигурации nginx (до `location ~ \.php$`):

```nginx
location = /mcp { rewrite ^ /index.php/mcp last; }
location ^~ /oauth/ { rewrite ^/oauth/(.*)$ /index.php/oauth/$1 last; }
location ^~ /.well-known/oauth- { rewrite ^(.*)$ /index.php$1 last; }
location = /.well-known/openid-configuration { rewrite ^ /index.php/.well-known/openid-configuration last; }
```

Перезапись адресов Joomla (Глобальная конфигурация → «Использовать перезапись адресов») при этом можно не включать. Если хотите включить её для всего сайта, нужна общая строка `location / { try_files $uri $uri/ /index.php?$args; }`. На панелях хостинга эти правила обычно добавляют в «дополнительные директивы nginx» сайта или просят у поддержки.

Проверка: `curl -i https://ваш-сайт/.well-known/oauth-authorization-server` должен вернуть 200 и JSON.

**Прокси и CDN.** Если сайт за прокси, который завершает HTTPS, Joomla может считать соединение небезопасным. Тогда сервер откажет по HTTPS-проверке. Настройте передачу схемы (`X-Forwarded-Proto`) либо временно отключите «Требовать HTTPS» (не рекомендуется для рабочего сайта).

**Кэш.** Изменения материалов и модулей могут не сразу появиться на сайте при включённом кэше. В наборе «Система» есть инструмент `cache.clear`.

## 8. Проверка

```bash
# без токена — должен быть ответ 401
curl -i -X POST https://ваш-сайт/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"ping"}'

# с токеном — список инструментов
curl -s -X POST https://ваш-сайт/mcp \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer dhmcp_ВАШ_ТОКЕН' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# настройки OAuth
curl -s https://ваш-сайт/.well-known/oauth-protected-resource
```

## 9. Обновление и удаление

- **Обновление.** Пакет при установке сам регистрирует источник обновлений. Новые версии появляются в **Система → Обновление → Расширения** (нажмите «Найти обновления»), как у любого расширения Joomla; файл проверяется по SHA-256. Настройки и токены сохраняются, схема базы обновляется автоматически, выбор администратора по включённым наборам не меняется (новый набор после обновления остаётся выключенным, пока вы его не включите). Можно и вручную: загрузить новый пакет поверх старого.
- **Удаление:** Система → Управление → Расширения → пакет «Dharma MCP». Вместе с ним **удаляются таблицы** (токены, журнал, клиенты OAuth). Резервные копии файлов в `tmp/dharma_mcp_backups/` остаются.

## 10. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| 401 «Missing or malformed Authorization header» при верном токене | хостинг не передаёт заголовок: см. раздел 7 |
| 403 «HTTPS is required» | сайт открыт по HTTP или прокси скрывает HTTPS: см. раздел 7 |
| 401 «Invalid or unknown token» | токен введён неверно или удалён; новый показывается только один раз |
| 403 «Token has expired» | истёк срок действия токена |
| 429 | превышен лимит запросов в минуту |
| В списке нет ожидаемых инструментов | набор выключен (Плагины → dharmamcp), у токена нет нужной области, или режим «только чтение» |
| Инструмент отвечает `confirmation_required` | это двухэтапное подтверждение: покажите предпросмотр пользователю и повторите вызов с кодом |
| «The Joomla user of this token is not allowed…» | у пользователя токена нет права Joomla на это действие |
| `/mcp` даёт 404 | выключен системный плагин адресов или запрос не доходит до Joomla (nginx без перезаписи): используйте `/index.php/mcp` и правила nginx из раздела 7 |
