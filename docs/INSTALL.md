# Установка и подключение

## 1. Требования

- Joomla 6.x, PHP 8.3 или новее, MySQL 5.7+/MariaDB 10.4+.
- **HTTPS** на сайте. По HTTP сервер откажет (токены нельзя передавать открыто). Для локальной проверки это можно отключить в настройках.
- Права на запись в `tmp/` (там хранятся резервные копии файлов, если включены наборы «Шаблон» и «Система»).
- Для набора «Магазин» — установленный Dharma Shop.

## 2. Получение пакета

**Готовый.** Самая простая ссылка всегда ведёт на последнюю версию:

```text
https://github.com/shivayanamahom/dharma-mcp/releases/latest/download/pkg_dharma_mcp.zip
```

Вставьте её в Joomla (раздел 3). Файлы всех версий лежат на странице [релизов](https://github.com/shivayanamahom/dharma-mcp/releases).

**Сборка из исходников.** Из корня репозитория:

```bash
./build.sh
```

Скрипт проверит все PHP-файлы и соберёт `dist/pkg_dharma_mcp-<версия>.zip`. Внутри пакета: компонент `com_dharma_mcp`, системный плагин адресов и четыре плагина-набора.

## 3. Установка на сайт

1. В админке Joomla откройте **Система → Установка → Расширения**, вкладка «Установить по URL-адресу», вставьте ссылку на пакет и нажмите «Проверить и установить». Если файл уже скачан, используйте вкладку «Загрузить файл пакета».
2. При первой установке сами включаются системный плагин «Система — Dharma MCP (адреса)», набор **Магазин** (если установлен Dharma Shop) и набор **Материалы и меню**.
3. Наборы **Шаблон** и **Система** остаются выключенными. Включайте их осознанно: **Система → Плагины**, группа `dharmamcp`. Пока набор выключен, его инструментов нет вообще.

## 4. Настройки

**Компоненты → Dharma MCP → Настройки.**

| Настройка | Что делает |
|---|---|
| Включить MCP-сервер | общий выключатель: при «Нет» сервер на любой запрос отвечает, что он отключён |
| Требовать HTTPS | по умолчанию да |
| Режим работы | *Только чтение* / *Чтение и черновики* (по умолчанию) / *Полный доступ* |
| Разрешить вход через сайт (OAuth) | нужен для Claude Desktop, claude.ai и ChatGPT: они входят через вашу учётную запись Joomla, токен не нужен |
| Разрешить программам регистрироваться самим | при первом подключении программа сама записывается на сайте; если выключить, новые программы подключить нельзя |
| Разрешить выдачу персональных данных | по умолчанию нет: имена, телефоны и адреса покупателей скрыты |
| Маскировать персональные данные | если выдача разрешена: показывать данные частично (например, `И*** П***`) |
| Срок хранения журнала | по умолчанию 90 дней |
| Лимит запросов в минуту | на один токен, по умолчанию 60 |

Режимы:

- **Только чтение** — ничего нельзя изменить.
- **Чтение и черновики** — новое создаётся неопубликованным; любое изменение того, что уже видят посетители (опубликованная статья, цена, статус заказа), ассистент делает только после вашего подтверждения; опасное (удаление, файлы, настройки) — тоже только после подтверждения.
- **Полный доступ** — изменения «вживую» выполняются без подтверждения; опасное (удаление, файлы, настройки, плагины) по-прежнему всегда с подтверждением.

## 5. Токен доступа

**Компоненты → Dharma MCP → Токены доступа → Создать.**

- **Пользователь Joomla** — от его имени выполняются действия. Токен не может больше, чем сам пользователь. Для набора «Система» и записи файлов нужен Суперпользователь.
- **Области доступа** — отметьте только то, что нужно: `shop:read`, `shop:write`, `content:read`, `content:write`, `template:read/write`, `system:read/write`, `customers:pii`.
- **Срок действия** — для опасных областей («Шаблон», «Система») ставьте короткий.
- **Разрешённые IP** — необязательно (адреса и сети вида `10.0.0.0/8`).

После сохранения Joomla **один раз** покажет токен вида `dhmcp_…`. Сохраните его в менеджере паролей: на сайте остаётся только «отпечаток» токена, восстановить сам токен нельзя.

Вместе с токеном Joomla сразу покажет **адрес сервера** и **готовую команду** для Claude Code с уже вставленным токеном. Все варианты подключения (Claude Code, Cursor и другие клиенты, Claude Desktop, claude.ai и ChatGPT) собраны на странице **Компоненты → Dharma MCP → Подключение**. Там же автоматическая проверка: отвечает ли сервер по своему адресу и доступны ли настройки OAuth, с подсказкой, что исправить.

## 6. Подключение клиентов

Адрес сервера: `https://ваш-сайт/mcp`. Если на сайте не включена «Перезапись URL» (Система → Общие настройки), используйте `https://ваш-сайт/index.php/mcp`. Нужный адрес всегда написан на странице **Компоненты → Dharma MCP → Подключение**.

> Названия кнопок в программах Claude и ChatGPT со временем меняются. Если что-то не совпадает, загляните в их справку.

**Claude Code** (по токену):

```bash
claude mcp add --transport http dharma https://ваш-сайт/mcp --header "Authorization: Bearer dhmcp_ВАШ_ТОКЕН"
```

**Claude Desktop / claude.ai:** Настройки → Коннекторы → добавить свой коннектор → адрес `https://ваш-сайт/mcp`. Откроется страница входа Joomla и экран согласия, где вы выбираете, что разрешить. Токен вводить не нужно.

**ChatGPT:** Настройки → Коннекторы → режим разработчика → добавить свой MCP-сервер → тот же адрес, тип авторизации OAuth.

**Cursor и свои скрипты:** адрес и заголовок `Authorization: Bearer …` в настройках клиента.

Доступ, выданный через вход на сайте (OAuth), можно отозвать там же, в **Токены доступа**: такие записи подписаны «OAuth: название программы».

## 7. Особенности хостинга

**Заголовок Authorization.** На части хостингов (когда PHP работает как CGI/FastCGI) Apache не передаёт PHP заголовок `Authorization`. Тогда сервер отвечает, что токен не передан, хотя он указан верно. Добавьте в `.htaccess` сайта, до правил Joomla:

```apache
RewriteEngine On
RewriteCond %{HTTP:Authorization} .
RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
```

Сервер читает `HTTP_AUTHORIZATION`, `REDIRECT_HTTP_AUTHORIZATION` и `apache_request_headers()`.

**Адреса `/mcp` и OAuth на nginx (и вообще без перезаписи адресов).** Короткие адреса `/mcp`, `/oauth/*` и `/.well-known/*` обслуживает системный плагин «Система — Dharma MCP (адреса)», но запрос должен дойти до Joomla. Это зависит от веб-сервера:

- **Apache:** достаточно штатного `.htaccess` Joomla (файл `htaccess.txt` нужно переименовать в `.htaccess`) и включённой перезаписи адресов.
- **nginx без перезаписи** (признак: страницы вашего сайта выглядят как `/index.php/...`, а `/mcp` отвечает 404 от nginx): адрес `https://ваш-сайт/index.php/mcp` работает сразу, для токенов этого достаточно. Для **OAuth (Claude, ChatGPT)** клиенты ищут настройки по адресам в корне сайта, поэтому добавьте в блок `server {}` конфигурации nginx (до `location ~ \.php$`):

```nginx
location = /mcp { rewrite ^ /index.php/mcp last; }
location ^~ /oauth/ { rewrite ^/oauth/(.*)$ /index.php/oauth/$1 last; }
location ^~ /.well-known/oauth- { rewrite ^(.*)$ /index.php$1 last; }
location = /.well-known/openid-configuration { rewrite ^ /index.php/.well-known/openid-configuration last; }
```

«Перезапись URL» в Joomla (Система → Общие настройки) при этом включать не обязательно. Если хотите включить её для всего сайта, нужна общая строка `location / { try_files $uri $uri/ /index.php?$args; }`. На панелях хостинга эти правила обычно добавляют в «дополнительные директивы nginx» сайта или просят у поддержки.

Проверка: `curl -i https://ваш-сайт/.well-known/oauth-authorization-server` должен вернуть 200 и JSON.

**Защита от ИИ-ботов (ошибка «Вы вошли на сервер, но затем он отклонил запрос Claude»).** Многие хостинги и панели включают блокировку по User-Agent: веб-сервер (nginx) отвечает обычной страницей «403 Forbidden» на запросы, подписанные как `ClaudeBot`, `Claude-User`, `GPTBot`, `OpenAI` и им подобными. Облачные Claude и ChatGPT подписываются так же, поэтому вход проходит (эти шаги идут под нейтральной подписью), а следующий запрос к `/mcp` блокируется до того, как попадёт в Joomla. Признак: в **Журнале вызовов** есть `oauth/consent` и `oauth/token` со статусом «Успешно», а после них ничего нет. Проверка из терминала:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://ваш-сайт/mcp -A "Claude-User" -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"ping"}'
```

Должно быть `401`. Если `403`, откройте правило блокировки (в панели хостинга: «Защита от ботов», «Блокировка по User-Agent» или в конфигурации nginx сайта, поиск по слову `ClaudeBot`) и сделайте исключение для адреса сервера `/mcp` и `/index.php/mcp`, остальной сайт можно оставить защищённым. Пример для nginx:

```nginx
set $ai_block 0;
if ($http_user_agent ~* "ClaudeBot|Claude-User|GPTBot|OAI-SearchBot|openai|PerplexityBot|CCBot") { set $ai_block 1; }
if ($uri ~ "^/(mcp|index\.php/mcp)$") { set $ai_block 0; }
if ($ai_block = 1) { return 403; }
```

Страница **Компоненты → Dharma MCP → Подключение** (версия 0.6.3 и новее) сама проверяет это и подсказывает.

**Прокси и CDN.** Если HTTPS завершается на прокси перед сайтом, Joomla может считать соединение незащищённым, и сервер откажет. Настройте передачу заголовка `X-Forwarded-Proto` или временно отключите «Требовать HTTPS» (для рабочего сайта так делать не стоит).

**Кэш.** При включённом кэше изменения материалов и модулей могут появиться на сайте не сразу. Кэш можно очистить инструментом `cache.clear` (набор «Система»).

## 8. Проверка

```bash
# без токена — должен быть ответ 401
curl -i -X POST https://ваш-сайт/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"ping"}'

# с токеном — список инструментов
curl -s -X POST https://ваш-сайт/mcp \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer dhmcp_ВАШ_ТОКЕН' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# настройки OAuth
curl -s https://ваш-сайт/.well-known/oauth-protected-resource
```

## 9. Обновление и удаление

- **Обновление.** Пакет при установке сам подключает источник обновлений. Новые версии появляются в **Система → Обновление → Расширения** (нажмите «Найти обновления»), как у любого расширения Joomla; загруженный файл проверяется по контрольной сумме SHA-256. Настройки и токены сохраняются, таблицы базы обновляются сами, а то, какие наборы включены, остаётся таким, как вы выбрали. Обновить можно и вручную: загрузите новый пакет поверх старого.
- **Удаление:** Система → Управление → Расширения → пакет «Dharma MCP». Вместе с ним **удаляются токены, журнал и данные входа через OAuth**. Резервные копии файлов в `tmp/dharma_mcp_backups/` остаются.

## 10. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| 401, «токен не передан» при верном токене | хостинг не передаёт заголовок `Authorization`: см. раздел 7 |
| 403, «нужен HTTPS» | сайт открыт по HTTP или прокси скрывает HTTPS: см. раздел 7 |
| 401, «токен недействителен» | токен введён неверно или удалён; сам токен показывается только один раз, при создании |
| 401, «срок действия токена истёк» | задайте новый срок или создайте новый токен |
| 429 | слишком много запросов за минуту: подождите или увеличьте лимит в настройках |
| В списке нет ожидаемых инструментов | набор выключен (Система → Плагины, группа dharmamcp), у токена нет нужной области доступа или включён режим «только чтение» |
| Ассистент просит подтверждение | так и задумано: он показывает, что именно изменится, и выполняет это только после вашего «да» |
| «The Joomla user of this token is not allowed…» | у пользователя, от имени которого работает токен, нет права Joomla на это действие |
| `/mcp` даёт 404 | выключен системный плагин адресов или запрос не доходит до Joomla (nginx без перезаписи): используйте `/index.php/mcp` и правила nginx из раздела 7 |
