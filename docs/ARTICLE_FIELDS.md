# Поля материалов (0.7.0)

Инструменты существующего набора «Материалы и меню» используют области `content:read/write`.

- `content.fields.list/get` — определения полей Joomla в контексте `com_content.article`.
- `content.fields.create` — черновик поля `text`, `url` или одиночного `list` с привязкой к конкретным категориям. Автоматический вывод выключен. Для списка нужны уникальные строковые `options`, названия вариантов совпадают со значениями.
- `content.fields.update` — название/метка, описание, категории. Требует подтверждения даже в полном режиме. Тип, машинное имя, варианты, настройки отображения и ACL сохраняются.
- `content.fields.set_state` — публикация, снятие с публикации и корзина с обязательным подтверждением. Физическое удаление не предоставляется.

Пример создания поля:

```json
{"title":"Версия Joomla","name":"versiya-joomla","type":"list","category_ids":[47],"options":["Joomla 6","Joomla 5 и 6","Joomla 4, 5 и 6"]}
```

После проверки опубликуйте поле через `content.fields.set_state`. Затем передавайте значения по машинному имени:

```json
{"id":62,"custom_fields":{"versiya-joomla":"Joomla 6"}}
```

Это аргументы `articles.update`; тот же `custom_fields` поддерживает `articles.create`. Пустая строка очищает значение, пропущенные поля сохраняются. `articles.get` возвращает определения и сырые значения в `custom_fields`, тексты помечены `user_content`.

Запись доступна для опубликованных полей подходящей категории, доступных в штатной форме. Проверяются ACL статьи, `core.edit.value` поля, занятость записи другим редактором и нативная форма Joomla. URL принимается только абсолютный HTTP(S). Множественные списки и другие типы в первой версии доступны на чтение. Для определения поля нужны права управления материалами, создания на компоненте и назначенных категориях либо редактирования конкретного поля. Глобальное назначение полей всем категориям, произвольные параметры плагинов и смена ACL через MCP не предоставляются.

Сохранение определения выполняет модель `com_fields/Field`, значений — `ArticleModel::save` через `com_fields`. Общий помощник `ArticleFields` фиксирует контекст, валидирует данные и сохраняет правила Joomla. Прямой записи SQL нет.

Старый `FieldsHelper` Joomla использует пользователя из сессии. На время операции ему передаётся пользователь токена, затем исходное значение восстанавливается в `finally`, включая ошибочные вызовы. Логин браузера не выполняется.

Проверка на локальном `test.test`:

```sh
php -d mysqli.default_socket=/Users/mksim/.kettle/run/mysql.sock dev/qa/fields_fixture.php seed
python3 dev/qa/fields_qa.py
```

Секреты временных токенов остаются в файле с правами 0600. Скрипт выполняет очистку точных ID своих записей в `finally` и восстанавливает режим сервера. Если процесс прерван, запустите `fields_fixture.php cleanup`.
