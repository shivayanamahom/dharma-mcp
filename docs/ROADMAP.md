## Этапы реализации

### Этап M0: Решения и архитектура
- [x] Согласование архитектуры самостоятельного расширения `com_dharmashop_mcp` без изменения ядра магазина.
- [x] Определение транспорта: Streamable HTTP (JSON-RPC 2.0).
- [x] Определение модели авторизации: Bearer API-токены (хэш в БД) + планируемый OAuth 2.1.
- [x] Решение о публичном репозитории на GitHub.

### Этап M1: Каркас компонента и базовый протокол
- [x] **Манифест и БД**: манифест `dharmashop_mcp.xml`, установочные SQL-скрипты таблиц токенов, логов и подтверждений.
- [x] **Админка (Joomla 6)**:
  - [x] Управление токенами доступа (создание, отзыв, выбор пользователя Joomla, скоупы прав).
  - [x] Журнал аудита вызовов (просмотр параметров, времени выполнения, статусов).
  - [x] Центр настроек (режимы работы, срок хранения логов — 90 дней, маскирование PII).
- [x] **Site Endpoint** (`/index.php?option=com_dharmashop_mcp&format=json`):
  - [x] Парсер JSON-RPC 2.0 запросов и уведомлений (202 Accepted без тела на notifications/*).
  - [x] Корректные HTTP-коды ответов (401 + WWW-Authenticate, 403, 400, 503).
  - [x] Аутентификация Bearer токенов с проверкой скоупов и срока действия.
  - [x] Диспетчер методов: `initialize`, `ping`, `tools/list`, `tools/call`.
- [x] **Базовые инструменты (M1)**:
  - [x] `ping` — проверка работоспособности сервера.
  - [x] `shop.info` — сводка о магазине (через MVC-модели `ProductsModel` и `OrdersModel` com_dharmashop без прямого SQL).
- [x] **Безопасность и PII (до M2)**:
  - [x] `PiiMasker`: маскирование email, телефонов, адресов в журнале аудита и ответах инструментов, управляемое `pii_enabled` и `mask_pii`.
- [ ] **Двухэтапное подтверждение**:
  - [ ] Механизм подтверждений (`confirmation_required`) — запланирован на M3 (в M1 создана только структура таблицы `#__dharmashop_mcp_confirmations`).
- [x] **Сборщик пакета**: `build.sh` для генерации `com_dharmashop_mcp.zip`.
